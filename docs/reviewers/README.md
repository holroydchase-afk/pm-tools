# Reviewer personas and review process

Generic, reusable review personas for any studio product, plus the loop they run in. Written so Atlas (and any project) can read them from here. Product-specific criteria and personal data are never kept in this repo.

| Persona | File | Use it to ask |
|---|---|---|
| Least tech-savvy user | `least-tech-savvy-user.md` | Can someone non-technical, on a phone, finish the job with plain words and big targets? |
| Recruiter on a phone | `recruiter-on-a-phone.md` | In 90 seconds, do I know what this is and whether the builder can ship? |
| Hiring manager on a laptop | `hiring-manager.md` | Do I see product thinking: why, tradeoffs, decisions? (Also: a cold read of a candidate's resume as the person the role reports to.) |
| Senior engineer | `senior-engineer.md` | Would I want this person or product wasting my team's time? Is it concrete or buzzwords? |

Process: `review-process.md` (numbered rounds, finding IDs, priorities, stop rule). The studio agents `ux-reviewer` and `qa-tdd` (studio-agents repo) run it.

Resume-specific reviewers (cold reviewer, engineering manager, hiring manager, mentor, writer) hold real resume rules and claims, so they stay private. Ask Chase.
