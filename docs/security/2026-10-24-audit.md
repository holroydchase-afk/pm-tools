# Security audit, 2026-10-24

_Product Studio, privacy-security agent. All 9 repos under holroydchase-afk: holroydchase-afk.github.io (portfolio), pm-tools, studio-agents, ccwatts, role-radar, energy-scanner, charlie, crew-clock, Hearth (private). ## Result
- **No leaked secrets.** gitleaks 8.21.2 over the full history of every branch in all 9 repos: 0 findings. No `.env`, key, certificate or credentials file was ever committed; Hearth's two `.env.example` files hold placeholders and the public Supabase URL only.
- **No personal data on public sites or repos.** The privacy scan (emails, phone numbers, claude.ai links, trigger ids) is clean on every public repo's current files, including the live portfolio and the Hearth demo bundle (sample `@example.com` people and a 555-01xx number). No comp figures are published. Older commits of the portfolio and crew-clock still contain a few claude.ai artifact links that were later removed; artifacts are private unless shared, and history is never rewritten, so this is accepted.
- **Gaps:** no repo ran a secret, dependency or code scan in CI; Dependabot alerts and security updates were off in every repo; private vulnerability reporting was off; no default branch is protected; Charlie had secret scanning off, and Crew Clock had push protection off.

## Chase's settings list
The cloud can read these settings but not change them. All links open the right page; about 10 minutes in total.

1. **Every repo at once** (2 min): https://github.com/settings/security_analysis → for **Dependabot alerts** and **Dependabot security updates**, click **Enable all** and tick **Automatically enable for new repositories**. If the page also offers **Private vulnerability reporting**, do the same.
2. **Charlie** (1 min): https://github.com/holroydchase-afk/charlie/settings/security_analysis → **Secret scanning: Enable**, then **Push protection: Enable**.
3. **Crew Clock** (30 s): https://github.com/holroydchase-afk/crew-clock/settings/security_analysis → **Push protection: Enable**.
4. **Private vulnerability reporting**, only if step 1 didn't offer it: on each link, **Private vulnerability reporting: Enable**.
